- Rejects generic SEO filler: each page must have specific, differentiated copy that answers concrete questions (what problem it solves, who needs it, what gets built, common features, technology, process, next step). Confidence: 0.8
- Wants comprehensive SEO implementation on content pages: metadata, canonical, OpenGraph, dynamic per-page metadata, structured data (Article + BreadcrumbList JSON-LD schema), internal links, sitemap, and RSS. Confidence: 0.9
- Wants internal linking between related content sections (solutions/services, industries, case studies, blog). Confidence: 0.6
- Develops in numbered phases (PHASE 4, PHASE 5, ...) driven by detailed structured specs; each phase is a self-contained build brief with explicit requirements and acceptance criteria. Confidence: 0.8
- Requires testing all routes after implementation (HTTP status codes, required page sections, 404 handling, static export output). Confidence: 0.8
- Never fabricates client names, statistics, revenue, performance improvements, user counts, or testimonials; when verified metrics are unavailable, uses qualitative outcomes and enforces this structurally in the data model (e.g. outcome `type: 'metric' | 'qualitative'`). Explicitly requires no fake statistics in content. Confidence: 1.0
- Content data models should mirror the backend/CMS schema (e.g. case study fields matching the Laravel `case_studies` migration) so real project data can be inserted through the CMS, with `published`/`featured` flags driving what renders. Wants "CMS-ready architecture" for new content systems. Confidence: 0.9
- Every blog/article page must follow a strict content structure: search intent, a clear upfront answer, detailed explanation with sections, real examples, pros/cons, related services, FAQ, and a CTA. Confidence: 0.9
- Wants lead magnets with gated download architecture: a downloadable asset (e.g. a checklist) unlocked by a capture form (name, email, company, role, main challenge) and wired into the lead pipeline as its own lead type. Confidence: 0.8

- Wants marketing attribution on lead capture: UTM source/medium/campaign/content, referrer, and landing page captured client-side and persisted (first-touch, e.g. sessionStorage) so a later conversion keeps the original source. Confidence: 0.8

- Wants clean architecture without unnecessary abstractions: "use clean Laravel architecture" but "do not build unnecessary abstractions" — avoid over-engineering and speculative generic layers; keep the build lean. Confidence: 0.7

- During audit/release phases, avoids scope creep: fix issues rather than add major new features unless required to resolve a problem ("Do not add major new features unless required to fix an issue"). Confidence: 0.7
- Wants conversion event tracking built into shared components (CTA clicks, form submissions with success/error, outbound booking/email/WhatsApp clicks), ideally provider-agnostic (dataLayer-style) so it plugs into GA/GTM without loading third-party scripts. Confidence: 0.7
